# Praca nad prototypem Blindstop

Przeczytaj README.md, docs/STATE.md, docs/DECISIONS.md, docs/GAME-RULES.md i docs/KNOWN-ISSUES.md.

Kontynuuj iteracje mockupu w `mockups/blindstop.html`. Zachowaj samodzielny HTML z osadzonymi assetami. Archiwalne generatory nie są aktualnym buildem. Nie edytuj ich ani historii bez konkretnej potrzeby.

Użytkownik daje kierunek, agent realizuje rutynowe poprawki samodzielnie. Nie wprowadzaj backendu, nowego frameworka, kont użytkowników ani dodatkowych trybów gry bez uzasadnienia i zlecenia użytkownika. Nie przywracaj starych ograniczeń repo kosztem późniejszych decyzji użytkownika.

Rozmawiaj po polsku; teksty interfejsu są po angielsku. Zachowaj nieruchome pozycje graczy podczas meczu, dedykowany przycisk Tap, stały układ akcji i ukryte paski przewijania listy. Nie dodawaj opisów dla recenzenta na ekranach aplikacji.

Po istotnych zmianach reguł aktualizuj dokumentację i copy. Sprawdź istotne scenariusze; `node tools/check.cjs` sprawdza logikę bez przeglądarki. Nie przedstawiaj tego jako dowodu poprawnego wyglądu lub działania dotyku na telefonie. W lokalnym środowisku wykonaj dostępne sprawdzenie przeglądarkowe, dokumentując faktyczny zakres. Nie deklaruj działania prawdziwego multiplayera.

Przed zmianami w repo przeczytaj jego obowiązujące instrukcje i sprawdź istniejące zmiany. Nie nadpisuj cudzej pracy. Nie twierdź, że zmiany są na GitHubie bez potwierdzenia skutecznego zapisu.
